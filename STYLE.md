Правила API «Библиотека»
URL — существительные во множественном числе, kebab-case. /books, /readers, /loans. Глаголов в пути нет (/getBooks, /createLoan запрещены).

Действия вне CRUD — только когда их нельзя выразить методом. Единственное исключение: POST /loans/{id}/return. Возврат — это не удаление (выдача остаётся в истории) и не простое изменение поля (сервер сам ставит дату и освобождает экземпляр).

id конкретного ресурса — в пути, фильтры — в query. GET /books/42, но GET /loans?status=overdue&reader_id=7.

Версия API — в servers: /v1. Несовместимые изменения выходят только в новой версии.

Поля JSON — snake_case. published_year, available_copies, due_date.

Коды ответа по смыслу:
201 + заголовок Location — создание;
204 без тела — удаление;
200 + пустой data — пустой список (не 404);
400 — запрос нельзя разобрать (неизвестное значение sort или status);
404 — нет ресурса с id из пути;
422 — данные не прошли проверку (видно по самому запросу);
409 — запрос корректен, но мешает текущее состояние (нет копий, лимит выдач, активные выдачи при удалении).

Отдельные схемы для запроса и ответа. CreateBookRequest и Book, CreateLoanRequest и Loan. Серверные поля (id, available_copies, registered_at, loaned_at, returned_at) — readOnly и в запросах отсутствуют. В схемах запросов additionalProperties: false.

Единый формат ошибок ErrorResponse. error.code (машинный код из фиксированного списка), error.message, error.details[] (поле, правило, пояснение), error.request_id.

Все списки — с пагинацией и обёрткой. Ответ { "data": [...], "pagination": { total, limit, offset, has_more } }. limit по умолчанию 20, максимум 100.

Опасные POST — с Idempotency-Key. Обязателен на POST /loans: повтор с тем же ключом не создаёт вторую выдачу. Ключ хранится 24 часа.
