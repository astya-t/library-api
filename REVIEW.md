Саморевью по чек-листу (слайды 32–35)

Ресурсы и URL. Пути названы существительными во множественном числе в kebab-case: /books, /readers, /loans. Единственное действие вне CRUD — POST /loans/{id}/return, причина описана в операции. Идентификатор ресурса передаётся в path, фильтры — в query. Версия /v1 указана в servers.

Методы и коды. Создание возвращает 201 и заголовок Location, удаление — 204, пустой список — 200. Код 409 используется для бизнес-конфликтов (нет свободных копий, лимит выдач, активные выдачи при удалении), 422 — для ошибок валидации, 404 — только для id из пути.

Схемы. Для запросов и ответов сделаны отдельные схемы, серверные поля помечены readOnly. available_copies вычисляет сервер, returned_at может быть null. Лишние поля в запросах запрещены через additionalProperties: false.

Ошибки и списки. Все ошибки используют один ErrorResponse со всеми кодами из задания. У списков есть фильтры, сортировка и пагинация, limit по умолчанию 20, максимум 100. На POST /loans требуется Idempotency-Key: описаны replay, mismatch, конкурентный повтор и хранение ключа 24 часа.

Документация. Операции разбиты по тегам Books, Readers, Loans, у всех есть summary, у ключевых — description. Добавлено 5 примеров, включая ошибки 422, 404 и 409. Общие части подключены через $ref.

Что можно улучшить. Описать ответ 401 в каждой операции, а не только в общем описании. Для больших списков использовать cursor-пагинацию вместо offset.
